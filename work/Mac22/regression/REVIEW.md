# Update22 native regression port review

Pass 1 — implementation: the complete existing Suite processor matrix is copied byte-for-byte, including failing pre-fix reproductions, signed strongest-L/R keys, unsupported Rack control isolation, LIFT/Gate filters/feedback/link policy, all supported module/rate/quality/layout combinations, block partitions, state/audio recall, allocation checks, routing, bands/slots and frozen internal-path bit equality. Eighteen baseline source files form the recursively resolved quoted-include closure. Their bytes come from the sealed Sidechain22 pre-fix snapshot and are listed in baseline-manifest.json.

Pass 2 — domain review: the six existing spectral controls retain their assertions and thresholds: pre-fix learned-noise failure, unchanged standalone spectral_tests.cpp current pass, integrated filter-bandwidth/white/pink/speech noise controls, level and advanced tests, and strongest-channel mono keys. Additional pre-fix mono failure and frozen modern PRO-denoise/LIVE-denoise-off exact comparison guard scope. The real speech WAV and its provenance/license are production test inputs; float WAV format is explicitly validated. No gain/attenuation threshold is relaxed. Suite baseline success means its defect predictions were observed; it is not a production pass.

Pass 3 — portability/evidence review: CMake uses pinned JUCE sources on macOS, native clang, precise floating point, and the host's exact native architecture. Windows-only prebuilt runtime is a local self-test option. Mac runs reject Rosetta, require the completed pipeline source fingerprint, hash executed binaries and every command/log/generated input, retain the original native report, and verify all 74 copied VST3 bundle digests before and after execution. The verifier rechecks retained evidence after transport. Expected nonzero controls require the exact diagnostic, so a crash or absent positive control cannot pass. A normal successful report is attached only after all tests finish. Test output is created only in a fresh destination.

Pass 4 — integration and polish: actual native VST3 binaries load through JUCE. All 74 products receive the original two-step state endpoint/fractional perturbation sweep. Five neutral/canonical state policies remain explicitly decoded from serialized XML, and SMARTDEESSER valid-profile context and invalid-profile atomic rejection are retained. Six affected key products receive the existing eight rate/quality/main-layout groups plus mono left/right physical key buses and full-waveform comparisons. Physical key buffers must remain unchanged, silent-main key leakage is forbidden, and positive key action accompanies phase-invariance checks. Existing unregistered GillBalanceUi21Tests is copied from the normal build, architecture-checked and executed, retaining its screenshot. Local Python tests exercise expected-failure handling, wrong-exit/wrong-token rejection, path escapes, empty host reports and matrix cardinality. Local native Windows proof is explicitly not macOS proof.

Limitations: this harness is a JUCE host and direct processor/core test suite. It does not establish physical FL Studio interaction, perceptual perfection, all conceivable automation/interleavings, or editor-only acquisition for every product. The broader production CTest and normal pipeline QualityHost gates remain required. SMART valid-profile state is a synthetic duration fixture, not successful human speech learning. Mac results require execution on both actual native CI architectures; Windows self-test never satisfies that requirement. VST3 learned-noise interaction is covered by processor/core tests, not a dedicated spectral-editor workflow. Absolute original command paths remain diagnostic; retained proof files use relocatable relative paths.

Run after the normal pipeline build:

```text
python3 work/Mac22/regression/run.py --source work --native "$RUNNER_TEMP/native" --build-root "$RUNNER_TEMP/gill-build" --destination "$RUNNER_TEMP/native/test-evidence/UPDATE22"
python3 work/Mac22/regression/run.py --verify "$RUNNER_TEMP/native"
```

The pipeline calls `verify_result(native, result=None)` or the CLI verifier on downloaded proof. The native report receives `update22_regression`, with result location, SHA-256, architecture and the pre-attachment report SHA-256. The saved result contains production and recipe input manifests, command vectors, expected/actual exits, log and executable hashes, all native bundle hashes, and retained proof file hashes. Compile intermediates may be omitted from transport; executed build executables referenced by proof_files must remain.
